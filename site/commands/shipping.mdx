## epx shipping

Reads and changes a site's shipping configuration, calculates its shipping fees and finds the
sites that ship to a postal code. Every command but find-sites requires `--site`; for an
unknown site, the lists show nothing and the quotes fail.

Its reads need no OAuth scope.
Its writes require the shipping.shipping\_manage scope.

**Command:** `epx shipping [flags]`, `epx shipping [command]`

**Flags:** only the [global flags](/commands#global-flags).

**Subcommands**

- [`epx shipping customers`](#epx-shipping-customers)\
  Read and change which shipping group each customer belongs to.
- [`epx shipping find-sites`](#epx-shipping-find-sites)\
  List the sites that ship to a postal code.
- [`epx shipping groups`](#epx-shipping-groups)\
  Read and change shipping groups.
- [`epx shipping quote`](#epx-shipping-quote)\
  Calculate the shipping fee of each method to a destination.
- [`epx shipping quote-minimum`](#epx-shipping-quote-minimum)\
  Calculate the lowest shipping fee to a destination.
- [`epx shipping quote-slot`](#epx-shipping-quote-slot)\
  Calculate the shipping fee of a delivery time slot.
- [`epx shipping zones`](#epx-shipping-zones)\
  Read and change shipping zones and their methods.

## epx shipping customers create

Assign a customer to a shipping group.

Assigns a customer to a shipping group of the site `--site` names: the JSON in `--file` names
the customer id and the group's, as in `{"customerId": "C001", "groupId": "vip"}`. A customer
that belongs to a group already is a conflict (exit 5): change its group with update.
Emporix checks neither the customer nor the group: unknown ids are assigned too.

Changes data: on a terminal, epx asks before it sends POST. `--yes` sends without
asking (required without a terminal, or with `--file` -); `--dry-run` prints the request
instead of sending it.

Requires the shipping.shipping\_manage scope.

**Command:** `epx shipping customers create [flags]`

**Flags**

- `--dry-run`\
  Print the request instead of sending it (excludes `-o`).
- `--file <PATH>`\
  JSON request body in PATH, sent byte for byte (- reads standard input; sending it then needs `--yes`; required).
- `-o, --output <format>`\
  Format of the response: json or yaml. Default: `json`.
- `--site <site>`\
  Site code, e.g. main (required).
- `--yes`\
  Send without asking (required without a terminal, or with `--file` -).

Also takes the [global flags](/commands#global-flags).

## epx shipping customers delete

Remove a customer from its shipping group.

Removes the customer CUSTOMER (the customer id) from its shipping group on the site `--site`
names. Emporix answers a CUSTOMER without a shipping group, or an unknown one, as one that
it removed (204 No Content).

Deletes data, which cannot be undone.
On a terminal, epx sends DELETE only once you type CUSTOMER at its prompt.
`--yes` sends without asking (required without a terminal);
`--dry-run` prints the request instead of sending it.

Requires the shipping.shipping\_manage scope.

**Command:** `epx shipping customers delete CUSTOMER [flags]`

**Flags**

- `--dry-run`\
  Print the request instead of sending it (excludes `-o`).
- `-o, --output <format>`\
  Format of the response: json or yaml. Default: `json`.
- `--site <site>`\
  Site code, e.g. main (required).
- `--yes`\
  Send without asking (required without a terminal).

Also takes the [global flags](/commands#global-flags).

## epx shipping find-sites

List the sites that ship to a postal code.

Lists the sites with a shipping zone that ships to a postal code: ZONES lists the zones that
Emporix returns with each site, and METHODS their shipping methods (`-o json` adds the
zones' destinations and fees). Emporix matched no site without `--country` on the tenant
tested.

Changes nothing: Emporix serves this read as POST with a JSON body, which the
flags make or `--body` gives whole.

No OAuth scope is needed.

**Command:** `epx shipping find-sites [flags]`

**Flags**

- `--body <FILE>`\
  Send the JSON request body in FILE as given (- reads standard input) instead of the one the other flags make.
- `--columns <names>`\
  Print only these columns of table and csv, in this order: comma-separated names (any case) among SITE, ZONES, METHODS.
- `--country <COUNTRY>`\
  The COUNTRY to ship to, a country code such as DE.
- `--limit <n>`\
  Print at most n items; paged reads stop early where they safely can (0: every item).
- `--no-headers`\
  Print table and csv without the header row.
- `-o, --output <format>`\
  Output format: table, json, yaml or csv (csv: the table's rows; json and yaml: the whole response). Default: `table`.
- `--postal-code <POSTAL_CODE>`\
  The POSTAL\_CODE to ship to (required without `--body`).
- `--stream`\
  Print items as JSON Lines as soon as they are checked, page by page on paged lists, reading up to 10000 pages where a list without it stops after 1000: a check failing on a later page exits 1 after the pages before it (excludes `-o`, `--columns` and `--no-headers`).

Also takes the [global flags](/commands#global-flags).

## epx shipping groups create

Create a shipping group.

Creates a shipping group of the site `--site` names from the JSON in `--file`: its id and
description, as in `{"id": "vip", "description": {"en": "Free shipping"}}`. A fee of a
shipping method applies to the customers of a group ([`epx shipping customers create`](/commands/shipping#epx-shipping-customers-create)) when
it names the group as its shippingGroupId. Emporix answers with the group's id; a group
with that id exists already: a conflict (exit 5).

Localized text in the body, such as a name, is a map of translations, e.g.
`{"en": "Netherlands", "nl": "Nederland"}`, as `-o json` of a read prints it, sent without a
Content-Language header (`--content-language` \*, the default), or with
`--content-language` LANGUAGE a string in that language, sent with that Content-Language,
e.g. `"Netherlands"` with `--content-language` en.

Changes data: on a terminal, epx asks before it sends POST. `--yes` sends without
asking (required without a terminal, or with `--file` -); `--dry-run` prints the request
instead of sending it.

Requires the shipping.shipping\_manage scope.

**Command:** `epx shipping groups create [flags]`

**Flags**

- `--content-language <LANGUAGE>`\
  The LANGUAGE of localized text in the body, or \* for maps of translations, sent without Content-Language. Default: `*`.
- `--dry-run`\
  Print the request instead of sending it (excludes `-o`).
- `--file <PATH>`\
  JSON request body in PATH, sent byte for byte (- reads standard input; sending it then needs `--yes`; required).
- `-o, --output <format>`\
  Format of the response: json or yaml. Default: `json`.
- `--site <site>`\
  Site code, e.g. main (required).

  Send without asking (required without a terminal, or with `--file` -).

Also takes the [global flags](/commands#global-flags).

## epx shipping quote

Calculate the shipping fee of each method to a destination.

Calculates what each shipping method of a site's zones that ship to a destination costs for
a cart total: one row per method, with its zone, its FEE and its shipping TAX CODE. With
`--customer`, the fees of the customer's shipping group apply ([`epx shipping customers`](/commands/shipping#epx-shipping-customers)).
Emporix answers a destination or cart total that no method serves, or an
unknown site, with 400 Bad Request (exit 1).

Changes nothing: Emporix serves this read as POST with a JSON body, which the
flags make or `--body` gives whole.

No OAuth scope is needed.

**Command:** `epx shipping quote [flags]`

**Flags**

- `--body <FILE>`\
  Send the JSON request body in FILE as given (- reads standard input) instead of the one the other flags make.
- `--cart-total <AMOUNT CURRENCY>`\
  The cart's total as AMOUNT CURRENCY, e.g. `"100 EUR"` (required without `--body`).
- `--columns <names>`\
  Print only these columns of table and csv, in this order: comma-separated names (any case) among ZONE, METHOD, NAME, FEE, TAX CODE.
- `--country <COUNTRY>`\
  The destination COUNTRY, a country code such as DE (required without `--body`).
- `--customer <CUSTOMER>`\
  The CUSTOMER id, whose shipping group's fees apply.
- `--language <language>`\
  Language of localized table text; a missing translation shows another, labeled (`-o json` prints all). Default: `en`.
- `--no-headers`\
  Print table and csv without the header row.
- `-o, --output <format>`\
  Output format: table, json, yaml or csv (csv: the table's rows; json and yaml: the whole response). Default: `table`.
- `--postal-code <POSTAL_CODE>`\
  The destination POSTAL\_CODE (required without `--body`).
- `--site <site>`\
  Site code, e.g. main (required).

Also takes the [global flags](/commands#global-flags).

Reads the shipping zones of a site. SHIPS TO lists the countries of the zone, each with
its postal codes when they are limited (a trailing \* matches every code that starts that
way).

No OAuth scope is needed.

**Command:** `epx shipping zones get ID [flags]`

**Flags**

- `--columns <names>`\
  Print only these columns of table and csv, in this order: comma-separated names (any case) among ID, NAME, DEFAULT, SHIPS TO.
- `--language <language>`\
  Language of localized table text; a missing translation shows another, labeled (`-o json` prints all). Default: `en`.
- `--no-headers`\
  Print table and csv without the header row.
- `-o, --output <format>`\
  Output format: table, json, yaml or csv (csv: the table's rows; json and yaml: the whole response). Default: `table`.
- `--site <site>`\
  Site code, e.g. main (required).

Also takes the [global flags](/commands#global-flags).

## epx shipping zones methods

Read and change the shipping methods of a zone.

Reads and changes the shipping methods of a zone of a site.

Its reads need no OAuth scope.
Its writes require the shipping.shipping\_manage scope.

**Command:** `epx shipping zones methods [flags]`, `epx shipping zones methods [command]`

**Flags:** only the [global flags](/commands#global-flags).

## epx shipping zones methods create

Create a shipping method of a zone.

Creates a shipping method of a zone from the JSON in `--file`: its id, name, active, fees
(each a cost from a minOrderValue, optionally for the customers of a shippingGroupId),
maxOrderValue and shippingTaxCode, as
[`epx shipping zones methods get SHIPPING_ZONE_ID ID -o json`](/commands/shipping#epx-shipping-zones-methods-get) prints one. Emporix answers
with the method's id; a method with that id exists already: a conflict (exit 5).
SHIPPING\_ZONE\_ID is the ID that [`epx shipping zones list --site S`](/commands/shipping#epx-shipping-zones-list) shows; an unknown one is not found.

Localized text in the body, such as a name, is a map of translations, e.g.
`{"en": "Netherlands", "nl": "Nederland"}`, as `-o json` of a read prints it, sent without a
Content-Language header (`--content-language` \*, the default), or with
`--content-language` LANGUAGE a string in that language, sent with that Content-Language,
e.g. `"Netherlands"` with `--content-language` en.

Changes data: on a terminal, epx asks before it sends POST. `--yes` sends without
asking (required without a terminal, or with `--file` -); `--dry-run` prints the request
instead of sending it.

Requires the shipping.shipping\_manage scope.

**Command:** `epx shipping zones methods create SHIPPING_ZONE_ID [flags]`

**Flags**

- `--content-language <LANGUAGE>`\
  The LANGUAGE of localized text in the body, or \* for maps of translations, sent without Content-Language. Default: `*`.
- `--dry-run`\
  Print the request instead of sending it (excludes `-o`).
- `--file <PATH>`\
  JSON request body in PATH, sent byte for byte (- reads standard input; sending it then needs `--yes`; required).
- `-o, --output <format>`\
  Format of the response: json or yaml. Default: `json`.
- `--site <site>`\
  Site code, e.g. main (required).
- `--yes`\
  Send without asking (required without a terminal, or with `--file` -).

Also takes the [global flags](/commands#global-flags).

## epx shipping zones methods delete

Delete a shipping method of a zone.

Deletes the shipping method ID of a zone. The time slots of delivery times that name it
stay and still name it.
SHIPPING\_ZONE\_ID is the ID that [`epx shipping zones list --site S`](/commands/shipping#epx-shipping-zones-list) shows; an unknown one is not found.
ID is the ID that [`epx shipping zones methods list SHIPPING_ZONE_ID --site S`](/commands/shipping#epx-shipping-zones-methods-list) shows; an unknown one is not found.

Deletes data, which cannot be undone.
On a terminal, epx sends DELETE only once you type ID at its prompt.
`--yes` sends without asking (required without a terminal);
`--dry-run` prints the request instead of sending it.

Requires the shipping.shipping\_manage scope.

**Command:** `epx shipping zones methods delete SHIPPING_ZONE_ID ID [flags]`

**Flags**

- `--dry-run`\
  Print the request instead of sending it (excludes `-o`).
- `-o, --output <format>`\
  Format of the response: json or yaml. Default: `json`.
- `--site <site>`\
  Site code, e.g. main (required).
- `--yes`\
  Send without asking (required without a terminal).

Also takes the [global flags](/commands#global-flags).
