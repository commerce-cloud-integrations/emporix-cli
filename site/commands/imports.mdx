## epx imports

Reads the Import Service, which imports master data from external sources into Emporix: configurations, their streams (each imports one source, an entity or files, into an Emporix type), the file queue of a file-based stream, schedules and runs, the errors and diagnostics of a run, the records imported, statistics, job groups, health thresholds and the tenant's import limits. Emporix allows these reads only with importtool.import\_trigger, with which epx also queues files for a stream, and starts, retries, cancels and schedules runs.

Its reads require the importtool.import\_trigger scope. Opt-in: epx requests a write-capable scope for a read only when given `--allow-write-scope`. Its writes require the importtool.import\_trigger scope.

**Command:** `epx imports [flags]`, `epx imports [command]`

**Flags:** only the [global flags](/commands#global-flags).

**Subcommands**

- [`epx imports configurations`](#epx-imports-configurations)\
  Read import configurations; start and schedule their runs.
- [`epx imports health-thresholds`](#epx-imports-health-thresholds)\
  Show the thresholds that rate the health of import streams.
- [`epx imports job-groups`](#epx-imports-job-groups)\
  List the job groups that scope the import statistics.
- [`epx imports license`](#epx-imports-license)\
  Show the tenant's import limits.
- [`epx imports records`](#epx-imports-records)\
  List the imported records of a type.
- [`epx imports runs`](#epx-imports-runs)\
  Read, cancel and retry import runs.
- [`epx imports statistics`](#epx-imports-statistics)\
  Show the import statistics of the last 30 days.
- [`epx imports streams`](#epx-imports-streams)\
  Read import streams and the records they imported; queue their files.
- [`epx imports types`](#epx-imports-types)\
  List the types that hold imported records.

## epx imports configurations delete-schedule

Delete the run schedule of a configuration.

Deletes the schedule of the configuration CONFIGURATION\_ID, which then runs only when it is triggered. Emporix answers alike when there is no schedule, also of a configuration that was deleted.

## epx imports configurations trigger

Start an import run of a configuration.

Starts an import run of the configuration CONFIGURATION\_ID, a DELTA run unless `--mode` FULL, and prints the run, QUEUED until a worker of the Import Service takes it. `--file` gives the body instead, e.g. `{"mode": "FULL", "dryRun": true, "streamIds": ["ID"]}` for a dry run of some streams, which maps and checks records but writes none. A configuration that has a run QUEUED, RUNNING or RESUMABLE already is a conflict (exit 5). Emporix answers a run that it refuses, e.g. of streams whose mappings were never published, as any other: the run ends ABORTED, which `--wait` reports. CONFIGURATION\_ID is the ID that [`epx imports configurations list`](/commands/imports#epx-imports-configurations-list) shows.

Changes data: on a terminal, epx asks before it sends POST. `--yes` sends without asking (required without a terminal, or with `--file` -); `--dry-run` prints the request instead of sending it.

`--wait` then reads the job again every `--poll-interval`, as [`epx imports runs get`](/commands/imports#epx-imports-runs-get) does and with the importtool.import\_trigger scope too, saying on standard error how its status changes, until it ends: then it prints the job and exits 0 if it ended SUCCEEDED, else 1. When `--wait-timeout` passes first, it prints the job as last read and exits 1; the job goes on. When a read of the job fails, it prints the job as last read and exits as that read does, e.g. 4 when the job is not found.

Requires the importtool.import\_trigger scope.

**Command:** `epx imports configurations trigger CONFIGURATION_ID [flags]`

**Flags**

- `--dry-run`\
  Print the request instead of sending it (excludes `-o`).
- `--file <PATH>`\
  JSON request body in PATH, sent byte for byte instead of the one that epx makes (- reads standard input; sending it then needs `--yes`).
- `--mode <MODE>`\
  The MODE of the run, DELTA when not given: FULL or DELTA.
- `-o, --output <format>`\
  Format of the response: json or yaml. Default: `json`.
- `--poll-interval <duration>`\
  How often `--wait` reads the run, 1s or more (only with `--wait`). Default: `5s`.
- `--wait`\
  Wait until the run ends, then print it.
- `--wait-timeout <duration>`\
  How long `--wait` waits, 1s or more (only with `--wait`). Default: `30m`.
- `--yes`\
  Send without asking (required without a terminal, or with `--file` -).

Also takes the [global flags](/commands#global-flags).

**Examples**

```sh
epx imports configurations trigger 7c9e6679-7425-40de-944b-e07fc1f90ae7 --mode FULL --wait
```

## epx imports configurations update-schedule

Upsert the run schedule of a configuration.

Sets when the configuration CONFIGURATION\_ID runs by itself, creating its schedule where it has none (an upsert), and prints the schedule. `--cron` is a Spring cron expression with six fields, seconds first, e.g. `"0 0 2 * * *"` for 02:00 every day (Emporix refuses one with five: 400 Bad Request), evaluated in `--timezone`, an IANA time zone such as Europe/Berlin. The schedule runs the configuration unless `--enabled=false`, which keeps it without running it: epx always sends enabled, as the schedule is replaced whole. `--file` gives the body instead. CONFIGURATION\_ID is the ID that [`epx imports configurations list`](/commands/imports#epx-imports-configurations-list) shows.

Changes data: on a terminal, epx asks before it sends PUT. `--yes` sends without asking (required without a terminal, or with `--file` -); `--dry-run` prints the request instead of sending it.

Requires the importtool.import\_trigger scope.

**Command:** `epx imports configurations update-schedule CONFIGURATION_ID [flags]`

**Flags**

- `--cron <EXPRESSION>`\
  The Spring cron EXPRESSION of the schedule, six fields (required without `--file`).
- `--dry-run`\
  Print the request instead of sending it (excludes `-o`).
- `--enabled`\
  Whether the schedule runs the configuration (`--enabled=false:` not). Default: `true`.
- `--file <PATH>`\
  JSON request body in PATH, sent byte for byte instead of the one that epx makes (- reads standard input; sending it then needs `--yes`).
- `-o, --output <format>`\
  Format of the response: json or yaml. Default: `json`.
- `--timezone <ZONE>`\
  The IANA time ZONE the expression is evaluated in.
- `--yes`\
  Send without asking (required without a terminal, or with `--file` -).

Also takes the [global flags](/commands#global-flags).

**Examples**

```sh
epx imports configurations update-schedule 7c9e6679-7425-40de-944b-e07fc1f90ae7 --cron "0 0 2 * * *" --timezone Europe/Berlin
```

## epx imports runs cancel

A QUEUED run is CANCELLED at once; a running one stops when it can, or with `--force` at once, which also unblocks its configuration. ## epx imports runs diagnostics

List the source rows behind a run's repeated keys and missing parents.

Reads the source rows behind a run's feed-quality counters, which do not fail a run: KIND is REPEATED\_KEY for a row whose KEY the run had already imported (OCCURRENCE times before), or UNRESOLVED\_PARENT for a child line whose parent was missing: LINKING FIELD and LINKING VALUE are the parent key it points at, WAITING LINES the lines waiting for that parent. The service keeps a capped sample per stream and kind; `-o json` says how many rows it recorded, its cap and whether a stream reached it (the run's counters give the totals). ## epx imports types

List the types that hold imported records.

Reads the target types that hold imported records ([`epx imports records`](/commands/imports#epx-imports-records) lists those of one). The service returns them whole, so they are read with one request.

Requires the importtool.import\_trigger scope. Opt-in: epx requests a write-capable scope for a read only when given `--allow-write-scope`.

**Command:** `epx imports types [flags]`

**Flags**

- `--allow-write-scope`\
  Opt in to requesting importtool.import\_trigger, which can also change data (required).
- `--columns <names>`\
  Print only these columns of table and csv, in this order: comma-separated names (any case) among TYPE.
- `--limit <n>`\
  Print at most n items; paged reads stop early where they safely can (0: every item).
- `--no-headers`\
  Print table and csv without the header row.
- `-o, --output <format>`\
  Output format: table, json, yaml or csv (csv: the table's rows; json and yaml: the whole response). Default: `table`.
- `--stream`\
  Print items as JSON Lines as soon as they are checked, page by page on paged lists, reading up to 10000 pages where a list without it stops after 1000: a check failing on a later page exits 1 after the pages before it (excludes `-o`, `--columns` and `--no-headers`).

Also takes the [global flags](/commands#global-flags).
