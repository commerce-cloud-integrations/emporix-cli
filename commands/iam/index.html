epx iam

Read and change IAM users, groups and access rights.

​
epx iam

Reads the tenant’s IAM (identity and access management) data: user accounts, the groups they belong to and what these may do: roles, permissions, scopes, resources, access controls and templates. Its writes change users, groups and their users, access controls and custom scopes, and with them who may do what in the tenant. Its reads require different OAuth scopes; the help of each names them. Its writes require different OAuth scopes; the help of each names them. Command: epx iam [flags], epx iam [command] Flags: only the global flags. Subcommands
  • epx iam access-controls
    Read, upsert and delete access controls.
  • epx iam groups
    Read, create, upsert and delete IAM groups and their users.
  • epx iam permissions
    Read IAM permissions.
  • epx iam resources
    Read IAM resources.
  • epx iam roles
    Read IAM roles.
  • epx iam scopes
    Read, upsert and delete OAuth scopes.
  • epx iam templates
    Read IAM templates.
  • epx iam users
    Read, create, replace and delete IAM users; read what they may do.

​
epx iam access-controls

Read, upsert and delete access controls. Reads IAM access controls, the scopes they grant the users of the groups that hold them, and upserts and deletes them. Its writes change who may do what in the tenant. Its reads require the iam.access_read scope. Its writes require the iam.access_manage scope. Command: epx iam access-controls [flags], epx iam access-controls [command] Flags: only the global flags. Subcommands
  • epx iam access-controls delete
    Delete an access control.
  • epx iam access-controls get
    Show one access control.
  • epx iam access-controls list
    List IAM access controls.
  • epx iam access-controls update
    Upsert an access control.

​
epx iam access-controls delete

Delete an access control. Deletes the access control ID. Emporix deletes only those made for the tenant, not the predefined ones (PREDEFINED in epx iam access-controls list). It changes who may do what in the tenant. Deletes data, which cannot be undone. On a terminal, epx sends DELETE only once you type ID at its prompt. --yes sends without asking (required without a terminal); --dry-run prints the request instead of sending it. Requires the iam.access_manage scope. Command: epx iam access-controls delete ID [flags] Flags
  • --dry-run
    Print the request instead of sending it (excludes -o).
  • -o, --output <format>
    Format of the response: json or yaml. Default: json.
  • --yes
    Send without asking (required without a terminal).
Also takes the global flags.

epx iam access-controls get

Show one access control. Reads IAM access controls. SCOPES counts the scopes an access control grants (-o json lists them); RESOURCE and ROLE are the ids of the resource and role older access controls refer to. list sorts by id unless --sort says otherwise; end another order with ,id:asc (e.g. name.en:asc,id:asc), as Emporix wants a direction on every field, so pages do not overlap. Requires the iam.access_read scope. Command: epx iam access-controls get ID [flags] Flags
  • --columns <names>
    Print only these columns of table and csv, in this order: comma-separated names (any case) among ID, NAME, SCOPES, PREDEFINED, RESOURCE, ROLE.
  • --language <language>
    Language of localized table text; a missing translation shows another, labeled (-o json prints all). Default: en.
  • --no-headers
    Print table and csv without the header row.
  • -o, --output <format>
    Output format: table, json, yaml or csv (csv: the table’s rows; json and yaml: the whole response). Default: table.
Also takes the global flags.

epx iam access-controls list

List IAM access controls. Reads IAM access controls. SCOPES counts the scopes an access control grants (-o json lists them); RESOURCE and ROLE are the ids of the resource and role older access controls refer to. list sorts by id unless --sort says otherwise; end another order with ,id:asc (e.g. name.en:asc,id:asc), as Emporix wants a direction on every field, so pages do not overlap. Requires the iam.access_read scope. Command: epx iam access-controls list [flags] Flags
  • --columns <names>
    Print only these columns of table and csv, in this order: comma-separated names (any case) among ID, NAME, SCOPES, PREDEFINED, RESOURCE, ROLE.
  • --language <language>
    Language of localized table text; a missing translation shows another, labeled (-o json prints all). Default: en.
  • --limit <n>
    Print at most n items; paged reads stop early where they safely can (0: every item).
  • --no-headers
    Print table and csv without the header row.
  • -o, --output <format>

epx iam access-controls update

Upsert an access control. Replaces the access control ID with the JSON in --file, or creates it with that id where none exists (an upsert): the scopes it grants (at least one), and optionally its name and description, domains and restrictedTo (CUSTOMER or EMPLOYEE: the only kind of group that may grant it, set when it is created only). With metadata.version as read, Emporix changes it only if that is still its version. Emporix answers with the id of one it created, and with nothing when it replaced one. It changes who may do what in the tenant. Localized text in the body is a map of translations, e.g. {"en": "Acme", "de": "Acme"}, as -o json of a read prints it, sent with Content-Language: *. Emporix refuses a string in its place. Changes data: on a terminal, epx asks before it sends PUT. --yes sends without asking (required without a terminal, or with --file -); --dry-run prints the request instead of sending it. Requires the iam.access_manage scope. Command: epx iam access-controls update ID [flags] Flags
  • --dry-run
    Print the request instead of sending it (excludes -o).
  • --file <PATH>
    JSON request body in PATH, sent byte for byte (- reads standard input; sending it then needs --yes; required).
  • -o, --output <format>
    Format of the response: json or yaml. Default: json.
  • --yes
    Send without asking (required without a terminal, or with --file -).
Also takes the global flags.

epx iam groups create

Create a group. Creates the group in --file, a JSON object with its name and the ids of the access controls that its users get (accessControls, from epx iam access-controls list), and optionally its id (Emporix makes one otherwise), description, userType (CUSTOMER, or EMPLOYEE, the default), templates, b2b.legalEntityId, restrictions and mixins. Emporix answers with the group’s id; a group with the id exists already: a conflict (exit 5). It changes who may do what in the tenant. Localized text in the body is a map of translations, e.g. {"en": "Acme", "de": "Acme"}, as -o json of a read prints it, sent with Content-Language: *. Emporix refuses a string in its place. Changes data: on a terminal, epx asks before it sends POST. --yes sends without asking (required without a terminal, or with --file -); --dry-run prints the request instead of sending it. Requires the iam.group_manage scope. Command: epx iam groups create [flags] Flags
  • --dry-run
    Print the request instead of sending it (excludes -o).
  • --file <PATH>
    JSON request body in PATH, sent byte for byte (- reads standard input; sending it then needs --yes; required).
  • -o, --output <format>
    Format of the response: json or yaml. Default: json.
  • --yes
    Send without asking (required without a terminal, or with --file -).
Also takes the global flags.

epx iam groups delete

Delete a group. Deletes the group ID. Emporix refuses to delete a group that users belong to (400 Bad Request, exit 1; epx iam groups users list ID lists them) unless --force-delete is given, which removes every user from it too. It changes who may do what in the tenant. Deletes data, which cannot be undone. With --force-delete, it deletes the group and the membership of every user of it with one request. On a terminal, epx sends DELETE only once you type ID at its prompt. --yes sends without asking (required without a terminal); --dry-run prints the request instead of sending it. --force-delete also requests the iam.assignment_manage scope. Requires the iam.group_manage scope. Command: epx iam groups delete ID [flags] Flags
  • --dry-run
    Print the request instead of sending it (excludes -o).
  • --force-delete
    Delete the group also when users belong to it, removing every user from it (requests iam.assignment_manage too).
  • -o, --output <format>
    Format of the response: json or yaml. Default: json.
  • --yes
    Send without asking (required without a terminal).
Also takes the global flags.

epx iam groups users create

Add a user to a group. Adds the user that --user names, of the kind that --user-type names (EMPLOYEE when left out), to the group GROUP_ID, or the one in --file, a JSON object with its userId and userType. Emporix answers with the id of the membership; a user already in the group is answered with a new id that is not the listed membership’s, and no second membership is made (read the members with epx iam groups users list). The user then gets the scopes of the group’s access controls; a group of a vendor takes only the vendor’s employees. GROUP_ID is the ID that epx iam groups list shows; an unknown one is not found. It changes who may do what in the tenant. Changes data: on a terminal, epx asks before it sends POST. --yes sends without asking (required without a terminal, or with --file -); --dry-run prints the request instead of sending it. Requires the iam.assignment_manage scope. Command: epx iam groups users create GROUP_ID [flags] Flags
  • --dry-run
    Print the request instead of sending it (excludes -o).
  • --file <PATH>
    JSON request body in PATH, sent byte for byte instead of the one that epx makes (- reads standard input; sending it then needs --yes).
  • -o, --output <format>
    Format of the response: json or yaml. Default: json.
  • --user <USER_ID>
    The USER_ID of the user to add: the ID that epx iam users list shows, or a customer’s id (required without --file).
  • --user-type <TYPE>
    The TYPE of user: CUSTOMER or EMPLOYEE.
  • --yes
    Send without asking (required without a terminal, or with --file -).
Also takes the global flags.

    Print at most n items; paged reads stop early where they safely can (0: every item).
  • --no-headers
    Print table and csv without the header row.
  • -o, --output <format>
    Output format: table, json, yaml or csv (csv: the table’s rows; json and yaml: the whole response). Default: table.
  • --stream
    Print items as JSON Lines as soon as they are checked, page by page on paged lists, reading up to 10000 pages where a list without it stops after 1000: a check failing on a later page exits 1 after the pages before it (excludes -o, --columns and --no-headers).

epx iam users scopes

List the scopes of a user. Reads the scopes a user is granted through their groups, sorted, without the tenant entry; a user without scopes lists nothing, like an unknown one. USER_ID is the ID that epx iam users list shows; an unknown one lists nothing. Requires the iam.scope_read scope. Command: epx iam users scopes USER_ID [flags] Flags
  • --columns <names>
    Print only these columns of table and csv, in this order: comma-separated names (any case) among SCOPE.
  • --no-headers
    Print table and csv without the header row.
  • -o, --output <format>
    Output format: table, json, yaml or csv (csv: the table’s rows; json and yaml: the whole response). Default: table.

epx iam users update

Replace a user. Replaces the user ID, an employee, with the JSON in --file, which gives each of firstName, lastName, preferredSite, preferredCurrency, preferredLanguage, department, backofficeUserNumber and groupIds: Emporix removes the user from every group and adds them to those of groupIds. An unknown ID is not refused: Emporix answers 204 No Content and adds that ID as a member of each group of groupIds, so those groups take effect for it. Check the ID with epx iam users get first; epx iam users groups delete-all ID removes it from every group it is in. It changes who may do what in the tenant. Changes data: on a terminal, epx asks before it sends PUT. --yes sends without asking (required without a terminal, or with --file -); --dry-run prints the request instead of sending it. Requires the iam.user_update scope. Command: epx iam users update ID [flags] Flags
  • --dry-run
    Print the request instead of sending it (excludes -o).
  • --file <PATH>
    JSON request body in PATH, sent byte for byte (- reads standard input; sending it then needs --yes; required).
  • -o, --output <format>
    Format of the response: json or yaml. Default: json.
  • --yes
    Send without asking (required without a terminal, or with --file -).
Also takes the global flags.
